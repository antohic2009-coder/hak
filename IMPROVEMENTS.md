## 0. Быстрые победы (низкий риск, заметный эффект)

### 0.1. Падение вывода на Windows `[код][проверено]`
При запуске `python -m dxa.predict` на русской Windows финальный `print` падает с
`UnicodeEncodeError: 'charmap' codec can't encode character '\u2192'` — символ `→`
в `dxa/predict.py:63` не кодируется в cp1251. Результаты (`results.xlsx/.csv`) при этом
уже записаны, но код возврата ненулевой — на защите это выглядит как «ошибка».
- **Фикс:** убрать `→`/эмодзи из `print`, либо в начале `main()` выполнить
  `sys.stdout.reconfigure(encoding="utf-8", errors="replace")`, либо обернуть финальный вывод.
- То же касается всех `print` с не-ASCII в `train.py`, `evaluate_final.py`.

### 0.2. Мёртвый код и мелочи
- `dxa/report.py:143-146`: переменная `ref` создаётся и не используется;
  `CurrentRequestedProcedureEvidenceSequence` ставится пустым — по DICOM SR он должен
  ссылаться на исследование. Для строгой валидации в PACS стоит заполнить.
- `dxa/pipeline.py:179-181`: поиск `src_it` линейным перебором внутри цикла — O(n²) на
  исследование; для больших наборов заменить на словарь `image_uid -> Item`.
- `dxa/report.py:45,57`: `overlay()` повторно вызывает `axis.centerline` / `roi.landmarks`,
  хотя измерения уже посчитаны в `_process_image` — двойной расчёт. Кэшировать ориентиры
  в `it.result`.

## 1. Устойчивость и безопасность

### 1.1. Память при чтении больших наборов `[код]`
`_iter_sources` / `_iter_zip` (`dxa/pipeline.py:57-85`) читают каждый файл целиком в память
(`p.read_bytes()`, `z.read(info)`). На закрытом тесте с тысячами снимков или крупным zip
возможен рост потребления ОЗУ. 
- **Как:** обрабатывать по одному файлу потоково (`ZipFile.open` + `pydicom.dcmread` из потока),
  ограничить одновременный буфер.

### 1.2. Коллизии имён при загрузке через API `[код]`
`create_job` (`dxa/api.py:81-83`) пишет файлы по `Path(f.filename).name` — два файла с одинаковым
именем из разных папок перезапишут друг друга, потеря данных.
- **Как:** префиксовать индексом/хэшем, сохранять относительный путь.

### 1.3. Безопасность `create_job_path` `[код]`
`POST /api/jobs/path` (`dxa/api.py:87-92`) позволяет прочитать **любой** каталог сервера.
Для локального АРМ это ок, но если сервис слушает 0.0.0.0 — это SSRF/LFI.
- **Как:** белый список корневых каталогов, отключение эндпоинта в публичном режиме,
  аутентификация (токен/сессия).

### 1.4. Задания не персистентны, нет отмены `[код]`
`_jobs` — словарь в памяти (`dxa/api.py:35`); рестарт теряет всё, нельзя отменить задание,
нет списка истории. Смонтированный том (`DXA_JOBS`) хранит только файлы, не состояние.
- **Как:** лёгкая БД (SQLite) для состояния, `DELETE /api/jobs/{id}` для отмены,
  `GET /api/jobs` для списка.

### 1.5. Ограничение размера и типа загрузок
Нет лимита размера и валидации MIME/расширения на `POST /api/jobs` — DoS-риск.
- **Как:** лимит `Content-Length`, проверка сигнатуры `DICM` на смещении 128.

### 1.6. Docker как непривилегированный пользователь `[код]`
`Dockerfile` работает от root. Добавить `RUN useradd -m app && USER app`, `--read-only` при запуске.

## 2. Качество модели и честность оценки (научная часть)

### 2.1. Независимость критериев в `quality_prob` `[проверено][отклонено]`
`probabilities()` (`dxa/model.py:101-107`) считает
`P(хотя бы одно) = 1 - ∏(1-pᵢ)`, предполагая **независимость** критериев. Для бедра «укладка»
и «область интереса» коррелируют (плохой снимок портит оба) → вероятность смещена.
- **Как:** калибровать общий `quality_prob` напрямую (логрегрессия на всех оценках критериев
  сразу) или через коппулу; сравнить AUC по честной CV.
  - **Результат:** прямая логистическая калибровка дала AUC **0.801** против **0.831** у
    текущего произведения; варианты `max` (0.815) и среднего (0.818) также хуже. Оставлено
    `1 - ∏(1-pᵢ)`: средняя вероятность 0.28 при доле брака 0.29.

### 2.2. Порог по F1 на малых выборках `[код]`
`_best_threshold` (`dxa/model.py:50-54`) максимизирует F1 на OOF при 6–36 положительных —
высокая дисперсия, риск подгонки. В отчёте это уже частично признано.
- **Как:** выбирать порог по кросс-валидации внутри обучающей части (вложенный CV),
  либо по ожидаемой стоимости/точности при фиксированном recall, усреднять по фолдам.

### 2.3. Оптимизм из-за итераций на одном наборе `[код]`
Детектор посторонних предметов правился три раза на тех же 99 снимках (`REPORT.md` 4.3),
правило области — дважды. Это классический multiple-comparisons-оптимизм.
- **Как:** зафиксировать hold-out фрагмент (как тестовый) и не смотреть на него до финала;
  либо честный вложенный протокол и перестановочный тест для каждого изменения.

### 2.4. Доверительные интервалы и статистика
ДИ считаются бутстрэпом по исследованиям — хорошо. Добавить:
- тест Макнемара / ДеЛонга при сравнении с baseline сокомандника (сейчас сравнение только по точечным AUC);
- чувствительность к числу фолдов/сидов (сейчас 5×5 — зафиксировано, но не показан разброс).

### 2.5. Расширение данных и аугментации
Нарушений мало (6–36 на критерий) — узкое место. 
- **Как:** доменные аугментации, сохраняющие физический смысл: поворот/сдвиг кадра (ось),
  обрезка (область интереса), синтетика для поверки. Уже используется для валидации —
  можно применять и для обучения порогов.

### 2.6. Критерий оси: разметка vs ТЗ `[код]`
F1 0.36 при AUC 0.85 из-за расхождения разметки врачей с порогом 5°. Решение следует ТЗ —
это правильный выбор, но для защиты стоит явно показать «confusion matrix разметки против ТЗ»
и объяснить, почему не подгоняем порог.

### 2.7. Верхняя граница позвоночника (половина Th12) `[код]`
Осознанно не реализовано (`REPORT.md` 4.4a). Если есть время — реализовать подсчёт позвонков
от крестца (лобовые пластинки/межпозвонковые промежутки), это закрыло бы пробел ТЗ.

### 2.8. Переносимость на другой аппарат `[проверено][частично исправлено]`
Правило области по ширине снимка (`SPINE_MIN_WIDTH_PX=290`) было настройкой под GE Lunar.
Добавлена анатомическая защита: при отсутствии тегов сначала проверяется форма вертикального
столба/диафиза, а ширина остаётся fallback. На размеченных данных итоговая область верна 249/249;
для полного переноса всё ещё полезен калибровочный профиль по `Manufacturer`/`StationName`.

### 2.9. Неопределённость масштаба пикселя `[код]`
`pixel_spacing` (`dxa/data.py:62-76`) отбрасывает неправдоподобные значения, но если тег
«врёт правдоподобно» — систематическая ошибка в сантиметрах. Прокинуть неопределённость
масштаба в решение (например, консервативный допуск) и показывать «точность измерения».

## 4. Продукт и пользовательский опыт

### 4.1. Веб-интерфейс `[код]`
Сделан «в стиле АРМ» — сильная сторона. Добавить:
- drag-and-drop, индикатор загрузки;
- отмену задания, список истории (`?job=` уже поддерживается — расширить до списка);
- фильтры по области/типу нарушения, сортировку, поиск по study_uid;
- увеличение снимка и подсветку конкретного ориентира (малый вертел, головка) при клике
  по критерию.

### 4.2. Экспорт
Добавить PDF-заключение на исследование (сводка + картинки с разметкой), сводку по браку
(какие критерии чаще), экспорт в HL7/FHIR при интеграции.

### 4.3. Human-in-the-loop
Кнопка «подтвердить/исправить решение врача» → сбор разметки → периодическое дообучение
порогов. Это естественный путь накопления данных (в наборе их мало).

### 4.4. Агрегация по исследованию
ТЗ и организатор иногда оценивают качество **исследования**, а не файла. Добавить колонку
`study_quality` (агрегат по снимкам исследования) и отдельный отчёт по исследованиям.

### 4.5. Документация для пользователя
README подробный; добавить короткий «шпаргалочный» раздел FAQ и схему архитектуры
(диаграмма потока DICOM → измерения → решение → отчёты).

## 5. Что бы я НЕ менял (сильные решения, которые стоит защищать)

- **Отказ от нейросетей в пользу измерений.** Измерение объяснимо, проверяемо и не
  переобучается на 6–36 примерах. Это главный аргумент — подчёркивать на защите.
- **Честная вложенная CV по исследованиям + бутстрэп по исследованиям.** Редкая для хакатонов
  строгость; противопоставить «подгонке порога на тесте».
- **Следование ТЗ там, где ТЗ задаёт число** (угол 5°, отступ 3 см), с честным показом
  расхождения с разметкой врачей.
- **Отказ от SigLIP** (AUC 0.852 с ним против 0.863 без) и уменьшение образа 5.4 ГБ → 752 МБ.
- **Устойчивость пакета:** ни один битый файл не роняет обработку (`processing_status=Failure`).
- **Доп. серии (PNG/SC/SR)** — выход за минимальные требования, интеграция с PACS.

## 7. Идеи на будущее (после хакатона)

- Ансамбль измерений с лёгкой нейросетью **только** там, где измерений не хватает
  (верхняя граница позвоночника), с обязательным перестановочным тестом.
- Самообучение порогов на накопленной разметке (active learning, п. 4.3).
- Мультиаппаратная калибровка (GE/Hologic/Norland) с профилями.
- Объяснения в терминах врача («позвоночник наклонён вправо на 7°») с генерацией
  текстовых протоколов.
- Мониторинг дрейфа: отслеживать распределение измерений на новых данных.
